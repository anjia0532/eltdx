# 7615 F10 / TQLEX API

`7615` 是通达信 F10 / 资料数据的 HTTP 网关，适合查询公司概况、题材、公告、财务报表、估值、研报等资料类数据。

它和 `7709` 行情主站是两条线：

| 类型 | 7709 | 7615 |
| --- | --- | --- |
| 连接方式 | TCP 长连接 | HTTP POST |
| 数据类型 | 行情、K 线、分时、成交明细、代码表 | F10、财务、题材、新闻公告、研报 |
| 使用入口 | `TdxClient` | `client.f10` 或 `F10Client` |
| 是否需要 7709 握手 | 需要 | 不需要 |

## 实盘验证状态

7615 通路**已实盘验证可用**（`000001`，耗时约 1.1 秒，5 项抽查全部返回真实数据）：

```console
$ python -m eltdx.f10_smoke --code 000001
[OK] company_profile tables=1 rows=[1]
[OK] hot_topics tables=1 rows=[10]
[OK] announcements tables=1 rows=[89]
[OK] theme_market tables=2 rows=[1, 13]
[OK] valuation tables=2 rows=[1, 20]
[OK] f10 smoke passed
```

关于「与 easy_tdx 对比」需要说明一点：**easy_tdx 1.20.7 里没有任何 7615 实现**
（全仓检索 `7615` 命中 0 次），所以 7615 这条通路**不存在同协议可对比对象**，
只能做实盘冒烟与跨协议互证。

## 与 7709 公司信息（F10 文本）的关系

`7709` 另有一条**文本型** F10 通路：`0x02CF` 列目录 + `0x02D0` 读内容，
拿到的是通达信客户端「F10」里那段 GBK 文本（例如 `000001.txt` = 平安银行最新提示）。
它与本页的 7615 Entry 是**两套独立数据源**，不是同一份数据的两种封装。

> ⚠️ 这两条命令（连同 `0x02C5`）的可用性**取决于原生模块版本**：
> 随 `v3.2.3` 发布、或从 PyPI 装到的 `_native` **不含**这 3 个命令，
> 调用会抛 `UnsupportedCommandError: unsupported command: 0x02cf`；
> 而用本仓库 Rust 源码编译出的 `_native` **已包含**它们，可直接使用
> `client.company_info.category(code, market)` / `.content(code, market, filename, offset, length)`。
> 版本落后的原因与编译方法见 CHANGELOG「未发布」。
> 旁证：easy_tdx 1.20.7 用它的纯 Python 实现能取回 `000001.txt` 的 23426 字节正文；
> 而同一份数据走 eltdx 的 `resources.read("000001.txt")` 只能拿到 `chunk_len=0`
> 的空块（说明该文件不经普通文件通路提供），所以文本型 F10 **必须**用
> `0x02CF`/`0x02D0` 读取，不能靠 `resources.read()` 绕。
> 若手上只有发布版原生模块，可暂用 7615 的 `company_profile` / `announcements` / `news` 等 Entry 替代。

> 这 3 个命令的差分 fixture 已于本轮补齐（`tests/native` 25/25 命令全覆盖），
> 载荷为 7709 F10 的真实结构：目录 = `count`(u16 LE) + `count × 152` 字节
> （64 name + 80 filename + 4 start + 4 length，GBK）；内容 = 12 字节头
> （正文长度在 `[10:12]`）+ GBK 正文。

## 基本用法

```python
from eltdx import TdxClient

client = TdxClient(timeout=3)
profile = client.f10.company_profile("000034")
topics = client.f10.hot_topics("000034")
notices = client.f10.announcements("000034")

print(profile.rows[0])
print(topics.rows[:3])
print(notices.rows[:3])
```

也可以只用 F10 HTTP 客户端：

```python
from eltdx import F10Client

f10 = F10Client(timeout=3)
print(f10.company_profile("000034").rows[0])
```

## 连接策略

自 `v3.2.0` 起，`F10Client` 和 `client.f10` 默认优先尝试 IPv4；IPv4 连接失败后继续尝试其他地址，包括 IPv6。要恢复系统默认地址顺序，可使用 `F10Client(prefer_ipv4=False)`，或设置 `client.f10.prefer_ipv4 = False`。

此策略仅作用于 F10 请求，不修改全局 DNS 函数，也不会把并发请求串行执行。保留 urllib 的环境代理、HTTP Host、HTTPS SNI 和证书校验。使用代理时，排序作用于客户端实际连接的代理地址，目标地址的解析由代理决定。

各地址依次连接并使用 `timeout`；这是地址优先级调整，不是 IPv4/IPv6 并行竞速。连接多个失败地址、DNS 解析和读取响应可能使总耗时超过一次 `timeout`。

## 返回结构

常规 F10 方法返回 `F10Response`；涨跌停列表返回 `LimitBoardLadder`，其 `raw` 和 `summary` 仍保留服务端原始结构：

| 字段 / 属性 | 含义 |
| --- | --- |
| `entry` | 实际调用的 TQLEX Entry |
| `request_body` | 实际发送的 JSON body |
| `error_code` | 服务端 ErrorCode |
| `ok` | `ErrorCode` 为 `0` 或空时为 `True` |
| `tables` / `result_sets` | 返回的表 |
| `rows` | 第一张表的行，适合最常见的单表结果 |
| `raw` | 原始 JSON 响应 |

每张表是 `F10ResultSet`：

| 字段 / 属性 | 含义 |
| --- | --- |
| `key` | ResultSetKey，没有时自动用 `table0`、`table1` |
| `columns` | 原生列名 |
| `rows` | 字典行 |
| `row_cells` | 带列位置的单元格，适合处理重复列名 |
| `count` | 行数 |

如果服务端返回重复字段名，`rows` 会自动保留后续列：

```text
T120, T120 -> row["T120"], row["T120__2"]
```

F10 字段以服务端返回的 `ColName` / `ColDes` 为准，很多 Entry 会返回 `T003`、`N001` 这类原生列名。单个调用方法的常用字段对照见 [methods/README.md](methods/README.md) 里的 F10 单页；遇到未列出的字段时，先看：

```python
print(response.tables[0].columns)
print(response.tables[0].rows[:2])
```

## 期货 F10（`qhf9_*`）

页面在 `http://page2.tdx.com.cn:7615/site/sketchf10/qhf10/html/<page>.html`，但**页面 HTML 无内联 callName**，Entry 在 `../js/skef10_qh_*.js` 里，且 JS 写的 Entry 是 `qhf9_*`（不带前缀），由 req.js 的 `CallTQL` 自动补 `CWServ.`——**直接调 `qhf9_*` 会返回 503**，必须用 `CWServ.qhf9_*`。区分商品（`qhf9_sp_*`）与股指（`qhf9_gz_*`）两套。

| 方法 | 作用 | 底层 Entry |
| --- | --- | --- |
| `qh_position_report(code, section, *, date, end_date, index)` | 持仓报告（`cjcc` 仓差层次 / `cjjg` 持仓结构 / `jcgc` 会员席位 / `ccjj` 成交均价 / `ykfx` 盈亏分析） | `CWServ.qhf9_{sp,gz}_ccbg_*` |
| `qh_basis_spread(code, section, period)` | 基差价差分析（`001` 走势 / `002` 数据 / `003` 日期列表 / `004` 价差数据） | `CWServ.qhf9_sp_jcjcfx` |
| `qh_warehouse_receipt(code, *, date)` | 仓单日报 | `CWServ.qhf9_sp_ckrb_ckrb` |
| `qh_inventory(code)` | 库存报告 | `CWServ.qhf9_sp_kcbg_kcbg` |
| `qh_variety_info(code, section)` | 品种资料（`pzjj` 简介 / `hyjj` 行业简介 / `xgzq` 相关证券） | `CWServ.qhf9_sp_pzzl_*` |
| `qh_index_info(code, section)` | 股指指数资料（`zsgk` 概况 / `lsjg` 历史价格），`code` 用 `399300` | `CWServ.qhf9_gz_zszl_*` |
| `qh_index_valuation(code, section, *, start, end)` | 指数估值（`dtpe` 动态市盈率 / `lspe` 历史市盈率 / `xjfh` 现金分红），`code` 用 `000300` 且需起止日期 | `CWServ.qhf9_gz_zsgz_*` |

!!! warning "期货家族三个必传参数（实测确认）"

    1. **持仓报告必须带日期**：`cjcc` / `cjjg` 只需单日 `date`；`jcgc` / `ccjj` / `ykfx` 需起止区间（`date` + `end_date`）。空日期返回 0 行。
    2. **仓单日报必须带日期**：`qh_warehouse_receipt("rb", date="20261020")` 返回 600 行，空日期 0 行。
    3. **指数代码不统一**：`qh_index_info` / `qh_weights` 用 `399300`，`qh_index_valuation` 用 `000300`（客户端写死），混用返回 0 行。

## 高级调用（需手动指定 Entry 和参数）

这是用户主动使用的底层入口，不会由 SDK 自动执行。没有封装到具名方法里的 Entry，可以手动指定 Entry 和参数直接调用：

```python
from eltdx import F10Client

f10 = F10Client(timeout=3)

response = f10.call(
    "CWServ.tdxf10_gg_gsgk",
    params=["8", "000034", ""],
)

print(response.rows[0])
```

对于 `HQServ.*` 这类使用自定义请求体的 Entry，直接传完整 body：

```python
response = f10.call(
    "HQServ.hq_nlp_tcihq",
    [{
        "ReqId": "200743",
        "setcode": 0,
        "code": "000034",
        "Page": -1,
        "PageSize": "-1",
        "modname": "mod_tcihq.dll",
    }],
)
```
