# v3.4.6

## 主要变化

本版只修 CLI 的代码位置参数解析，不涉及 Python API 与协议实现：此前
`eltdx kline sh000016 --period day` 会把代码按字符拆开报错，`eltdx ex quote / bars / minute / txn`
会把代码列表整个传给只收单个字符串的接口、在编码阶段崩溃。两类命令现在都能正常取数。

- **`kline` 位置参数按单个代码解析**：`nargs="?"` 拿到的是裸字符串，`_codes()` /
  `_single_code()` 现在按单个代码处理，不再逐字符展开；`000001,600519`、`'SZ 000001'`
  等既有写法不受影响。
- **`ex` 单码接口统一走 `_single_code()`**：`quote` / `bars` / `minute` / `txn`
  收到多个代码时明确报「只接受一个代码」，而不是在底层 `code.encode()` 处抛 `AttributeError`。

## 修复内容

- **`eltdx kline sh000016 --period day` 报「该命令只接受一个代码，收到 8 个」**：
  根因是 `kline` 的 `code` 位置参数为 `nargs="?"`（argparse 返回裸字符串），
  而 `_codes()` 直接按序列迭代，把 `sh000016` 拆成 `['s', 'h', '0', ...]`。
  现在 `_codes()` / `_single_code()` 接受裸字符串与 `None`（未传代码按空列表处理，
  报错信息统一为「该命令只接受一个代码，收到 0 个」）。
- **`eltdx ex quote --market 33 IFL0` 等崩溃**：`ex` 的 `code` 位置参数为
  `nargs="*"`（列表），`cmd_ex` 之前把 `['IFL0']` 裸传给 `get_instrument_quote()`
  等只收 `str` 的方法；`bars` / `minute` / `txn` 同样问题，一并改走 `_single_code()`。
- 两处缺陷自 CLI 首个提交即存在（非近期回归），已补回归测试锁定：
  `kline` 三种代码写法（代码在前 / 选项在前 / 多码拒绝）与 `ex` 单码、多码。

## 升级

```bash
python -m pip install --upgrade "eltdx==3.4.6"
```

- 从 `v3.4.5` 升级**无破坏性变更**：只修 CLI 位置参数解析，Python API 与协议实现不变。
- 之前绕开 `eltdx kline` / `eltdx ex` 而直接调 Python API 的用法不受影响。
- 仍然提供各平台预编译 wheel（abi3，覆盖 Python 3.10—3.14），安装无需本地 Rust 工具链。
