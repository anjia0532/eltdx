# v3.3.0

## 主要变化

- **分钟级 K 线支持右端点时间戳**：`client.bars.get()`、`ExTdxClient.get_instrument_bars()`、
  `ExTdxClient.get_history_instrument_bars_range()`、`MacClient.get_stock_kline()` 新增
  `bar_time` 参数。默认 `"start"` 是通达信原始语义（上午最后一根 5 分钟 K 标 `11:25`、
  下午第一根标 `13:00`）；传 `"end"` 则得到右端点（同一根标 `11:30`），便于与 Tushare、
  同花顺对齐。日线及以上周期不受影响。
- **补齐 3 个 7709 文本型 F10 命令**：`0x02c5`（板块元信息）、`0x02cf`（公司信息目录）、
  `0x02d0`（公司信息正文）现已可用，配套 `eltdx.api.company_info` 的
  `category()` / `content()` 与 `python -m eltdx.f10_smoke` 冒烟脚本。
- **新增 CLI 调用**：`eltdx ex`、`eltdx f10`、`eltdx kline` 等子命令可直接从命令行取数。
- **资金流空数据主机故障转移**：`client.money_flow.daily()` 在直连 `0x0ffc` 返回空数据时，
  改为按延迟顺序逐台专用主站实测，拿到非空即返回；**所有主站都为空时返回空而不是抛错**
  （新股、退市等本来就没数据的标的不会被误报成故障）。重试次数有上界：一次调用只探测一轮且整批共享，
  不会造成连接放大。
- **本地行情文件读写**：`eltdx.offline` 支持 `.day` / `.lc1` / `.lc5` / `.5` 及扩展市场
  `.day` 的读取与写回，纯标准库实现、不联网。
- **扩展行情并发探活 + 失败自动负载均衡**：`ExTdxClient.connect()` 现在用真实业务命令
  **并发**探测全部候选主机，只把真正应答的按延迟排到前面；失败判定改为**命令级**，
  失败主机立即被排除、请求自动落到其余健康主机，成功一次即自动恢复其健康标记。
  探活「首个可用即返回」，实测默认 `ExTdxClient()` 的 `connect()` 由「必然失败」
  变为 **0.08 秒**。新增 `healthy_hosts` / `unhealthy_hosts` / `refresh_hosts()`
  与 `auto_failover` / `probe_on_connect` / `probe_timeout` / `max_probe_workers`。
- 差分 fixture 覆盖率提升到 **25/25** 个 7709 命令，`tests/native` 由 97 项增至 103 项。

## 使用示例

```python
from eltdx import TdxClient

with TdxClient(timeout=3, pool_size=3) as client:
    raw = client.bars.get("sz000001", period="5m", count=48)
    aligned = client.bars.get("sz000001", period="5m", count=48, bar_time="end")
    print(raw.bars[-1].time, "->", aligned.bars[-1].time)
```

`bar_time` 只影响分钟级周期。周期时长取自响应里已解析的 `period_raw` / `period_param_raw`，
因此 `period="13m"` 这类多分钟扩展周期也会按 13 分钟偏移；`get_history_instrument_bars_range()`
只按日期范围查询、拿不到周期时长，故与 `easy_tdx` 一致地**拒绝** `"end"` 并抛 `ValueError`，
而不是静默返回错误时间。详见[7709 K 线接口](methods/7709-K线周期线.md)。

## 修复内容

- **`MacClient.get_stock_kline()` 完全不可用**：`SymbolBarCmd` 帧体少 1 个标志字节
  （`bbb` 应为 `bbbb`），服务端对任何标的都只回 1 字节空体。已在 7709 与 7727 两条通道
  分别验证修复。
- **港股 `ds/*.day` 成交额口径错误**：该槽位是 `float32`，按整数读会得到 IEEE-754 位模式。
  新增 `ExDailyBar.hk_stock_amount` 给出正确值。
- **本地行情文件读取过于严格**：`.day` / `.lc1` / `.lc5` 现在忽略末尾不足一条记录的残尾，
  通达信写盘中断留下的截断文件可以正常读出。
- **`normalize_code` 缺 `5xxxxx` 号段**：沪市 ETF / LOF / 货币基金 / 权证（`510300`、
  `511360`、`518850`、`501050`、`580000` 等）此前抛 `unable to infer market`，现正确识别；
  同时补上 `4xxxxx` → 北交所。
- **`eltdx ex markets` 不再默认索取市场表**：改用 `--probe-server` 才走网络。实测所有内置
  主站都不回应 `get_markets`（`0x23f4`），原行为是每台主机各等满一个连接超时；枚举本身
  就是完整且权威的市场表。该命令耗时 **30.6 秒 → 0.3 秒**，输出逐字节不变。
- **`ExTdxClient` 故障转移形同虚设，导致查不到场外基金**：旧实现失败后重连**仍回到同一台**
  （`_ordered_hosts()` 把当前主机排首位），且失败判定只看 TCP——16 台内置主机 TCP 全部可连，
  换台条件永不成立。表现为默认 `ExTdxClient()` 调 `get_instrument_info()` 必然超时，
  `016947`（国泰利安中短债A，`market=33` / `category=8`）这类场外基金查不到。
  根因**不是**「场外基金不收录」，也不是协议错误。
- **`ping_all()` / `from_best_host()` 只看 TCP 等于没有区分度**：旧版让 16 台内置主机
  全部返回「健康」，`from_best_host()` 实际是随机挑一台。现在探活要求主机真的应答业务
  命令，实测只返回 **1/16**。

## 移除

- **删除 `ExTdxClient.send_setup()` 与 `eltdx.ex.commands.setup`**：该握手帧是上游从未调用的
  常量，被包装成公开方法后调用会让服务器不再应答任何命令，等于把连接打死。
- `eltdx.ex.mac_commands` 不再重复定义命令类，改为再导出 `eltdx.mac.commands` 的同一批实现。

> 以上移除与 `eltdx.offline`、`MacExClient`、`MacClient.get_stock_kline` 帧格式等改动，都只涉及
> 从未随正式版本发布过的代码；从 `v3.2.3` 升级的使用者不受影响。完整清单见[变更记录](../CHANGELOG.md)。

## 升级

```bash
python -m pip install --upgrade "eltdx==3.3.0"
```

本版本的 `_native` 已包含 3 个新的 F10 命令。若你此前装的是随 `v3.2.3` 发布的原生模块，
升级后 `0x02c5` / `0x02cf` / `0x02d0` 即可用，无需额外操作。
