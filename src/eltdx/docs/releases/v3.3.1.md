# v3.3.1

## 主要变化

- **MCP 的 F10 响应新增中文字段标签**（合并上游 PR #17）：公司概况、热点题材、财务报表和
  公司资讯的 F10 结果新增按 Entry / 请求分区解析的 `field_labels`、`unmapped_fields` 与
  `field_notes`；资产负债表、利润表和现金流量表进一步按 `nhytype` 区分通用企业、银行、
  券商和保险模板。原始 `columns` / `rows` / `row_cells` 全部保留，属**纯增量、向后兼容**。
  同一字段编号在不同接口或不同行业下含义不同（例如 `T039`），因此映射一律带上下文解析，
  不做全局映射。

## 修复内容

- **客户端资源延迟回收（引用环）**：`TdxClient` 与它的子服务此前互持强引用——子服务持有
  client 的 bound method（`price_resolver` / `metadata_sink` / `transport_factory`），
  client 又持有这些子服务，构成引用环，引用计数永远到不了 0，底层 Rust worker 线程只能等
  分代 GC 才回收。实测（关闭 gc）10 个未 `close()` 的客户端会滞留约 **5 条线程/个**；
  现在**每个 0 条**，`del` 后立即释放。做法：子服务改为持弱引用（bound method 用
  `weakref.WeakMethod`，其余用 `weakref.ref`），`TdxClient` 显式声明 `__weakref__` 槽位
  使其可被弱引用。正常使用（`with` 或显式 `close()`）的既有行为完全不变。
- **扩展行情并发探活早退不再残留线程**：`probe_ex_hosts(stop_after_first=True)` 此前用
  `shutdown(wait=False)`，而被放弃的在途探活线程要等满 `probe_timeout` 才退出——实测 6 次
  创建客户端会累积到 **97 条 OS 线程**。现在早退时**主动中断**在途连接（关闭其 socket，
  使阻塞中的 `connect()` 立即失败）后再 `shutdown(wait=True)`：同样场景回落到 **5 条**，
  而 connect 耗时仍是 **0.08 秒**，早退的速度优势保持不变。

## 行为变更

- **`TdxClient(...).helpers.foo()` 这类临时链式调用不再可用**：打断引用环的同时，也取消了
  「子服务替 client 续命」的副作用。把客户端绑定到变量后再调用即可，文档与全部示例一直是
  这样写的；`with TdxClient() as client:` 不受影响。

## 升级

```bash
python -m pip install --upgrade "eltdx==3.3.1"
```

本版本同时提供各平台预编译 wheel（abi3，覆盖 Python 3.10–3.14），安装无需本地 Rust 工具链。
