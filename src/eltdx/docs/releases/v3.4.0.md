# v3.4.0

## 主要变化

- **新发现的免登录 7615 接口合并封装成 8 个 `section` 驱动方法**（个股 / ETF 基金 / 板块 / 指数 / 大盘合并为一套 API）：

  | 方法 | section 数 | 覆盖 |
  | --- | --- | --- |
  | `client.f10.shareholders()` | 11 | 股东人数与股价比较、同行业人数排名、控股股东、十大股东 / 十大流通股东、十大债券持有人、重要股东持股变动、机构持股汇总 / 分类汇总 / 持仓明细、股东增减持计划 |
  | `client.f10.capital_structure()` | 5 | 股本结构、股本变动、股票回购、限售流通与解禁明细 |
  | `client.f10.business_report()` | 6 | 主营业务、主营构成、前五名客户、前五名供应商、产品价格、财务指标大幅变动说明 |
  | `client.f10.industry_analysis()` | 10 | 同业对比、分红排名、规模、估值、行业新闻、行业研报、市场份额、行业汇总、可比公司与可比公司资料 |
  | `client.f10.trading_report()` | 11 | 融资融券（近期 / 近 6 个月）、大宗交易、龙虎榜、沪深股通、涨跌停分析、可转债、主力盘口、研报席位、科创板标记 |
  | `client.f10.fund_report()` | 30 | ETF / 场外基金：名称、基金经理、管理人、基本概况、交易席位、规模与份额、净值序列 / 区间收益 / 同类排名 / 分红、资产配置、行业分布、重仓股变动、持仓明细、财务指标、费率 / 公告 / 资讯、ETF 标记、融资融券、基金评级、同类对比 |
  | `client.f10.market_report()` | 20 | 板块：名称、基础资料、说明、交易数据、板块资金、成份股数据、三点分析、成份股财务对比、成份股候选数据、异动分析；指数：信息、概况、跟踪标的、资金动向、成份股资金、今日提示；大盘：基本信息、两融、新股分析、市场概览 |
  | `client.f10.digest()` | 8 | 最新提示、公司概要、公司大事、公司新闻、公司公告、公司研报、路演、投资者互动 |

  四族 Entry 全部是**纯 HTTP POST** 到 `http://static.tdx.com.cn:7615/TQLEX`，**不需要登录、不需要 7709 握手**：`CWServ.tdxf10_gg_*`（个股）、`CWServ.skef10_jj_*`（ETF / 基金）、`CWServ.skef10_bk_*` / `CWServ.skef10_zs_*`（板块 / 指数）、`CWServ.skef10_dpzx_*`（大盘指数）。

- **方法数不因标的类型膨胀**：个股、ETF / 场外基金、板块、指数、大盘**共用同一批方法**，靠 `section` 分派；旧方法只补 `section`，不新增同义方法：

  - `profit_forecast(code, section="ylyctj")` 新增 `ylycmx` / `yzyq` / `tzpjtj` / `ycpjyjbg`（默认行为与参数不变）。
  - `shareholder_change_plans(...)` 委托给 `shareholders(code, section="plan", ...)`，签名与请求完全不变。
  - `business_composition(code, report_date=None)` 委托给 `business_report(code, "composition", report_date=...)`，仍会自动取最新报告期。
  - `company_news(code, section="finance_review")` 走财报点评（`CWServ.tdxf10_gg_cwfx_cbdp`）。
  - 各方法对未知 `section` 抛 `ValueError` 并列出全部合法取值。

- **`eltdx f10` 命令行**：新增 `eltdx f10 <action> [CODE] --section ...`，action 覆盖上述 8 个方法与既有 F10 页面；`eltdx f10 sections` 不联网列出全部合法 `--section`（并标出默认值）；`eltdx f10 call --entry ... --params '[...]'` 可直接调用任意 Entry。`-o table / csv / jsonl` 会把 TQLEX 回包展开成数据行，`-o json`（默认）保留完整回包便于排查。

- 文档新增 6 个接口页（股东研究 / 股本结构 / 行业分析 / 交易数据 / 基金与 ETF / 板块与指数），`F10_7615.md` 补三节 Entry 对照（个股其余 Entry、`skef10_jj_*` 的 7 个菜单页与 13 个 Entry、`skef10_bk_* / skef10_zs_* / skef10_dpzx_*`）；接口目录的 7615 层从 22 项扩到 28 项，新增 `交易数据`、`基金与市场` 两个分类。

## 行为变更

- **`client.money_flow.history()` 改走 7615，不再使用 7709 category 22**：签名变为
  `history(code, *, days=60, start=0, count=None, include_raw=False, batch_size=75)`，
  请求 `CWServ.tdxf10_gg_sj` 的 `{"Params": ["zjlx_sj", code, str(days), code]}`（`days` 只接受 `3` / `5` / `10` / `20` / `60`），
  返回新的 `eltdx.models.money_flow.FundFlowRangeSeries`（已由 `eltdx.models` 导出），
  列语义固定为 `N004=主力净额`、`N005=超大单净买入`、`N006=大单净买入`、`N007=主买净额`、`N009=上市日期`，其余原始列原样保留，不做语义臆测。
  `start` / `count` 改为拿到响应后的客户端切片。
  旧 `0x052d` category 22 在 18 台可达主站上一律只回 2 字节 `0000` 空 payload，本版正式标注为废弃；`period="flow"` 不再有效，
  `client.bars.get(..., period="flow")` 会抛 `ValueError` 并指向新方法。旧 DTO `FundFlowHistorySeries` / `FundFlowHistoryRecord` 仍由 Rust 侧导出。
- `eltdx money-flow` 增加 `--days 3|5|10|20|60`：不传仍走 7709 `0x0ffc` 当日 16 分档，传了走 7615 区间通道。
- `eltdx f10 detail` 需要两个位置参数（`detail_type` 与 `record_id`），例如 `eltdx f10 detail xw 22075813`。
- 新增的 section 驱动方法在部分分区对部分标的**返回 0 行**（例如个股无债券 / 无龙虎榜记录、基金无债券配置），属于「接口通、该标的无数据」，与接口不可用无关。

## 修复内容

- `client.f10.fund_report(section="finance")` 的默认取表从 `cwzb` 改为 `zcfzb`：实测 `cwzb` 对 ETF 返回 0 行，`zcfzb`（资产负债表）返回 28 行。
- `client.f10.trading_report(section="margin_history")` 使用 `CWServ.tdxf10_gg_sj` 的 `rzrq_sj`，第三参数固定 `"0"`（该参数不是窗口开关），可稳定取到近 6 个月、每只约 122 行。
- `client.bars.get(..., period="flow")` 的报错信息不再提及已废弃的 `0x052d` category 22 和 `count=`，改为指向 `money_flow.history(code, days=...)`。
- `F10Client` 的 `company_profile` / `dividend_financing` / `finance_report` / `governance` 等既有方法的合法 `section` 取值在文档中补全，未再出现「文档只列 2 个、实际可用 10 个」的偏差。

## 升级

```bash
python -m pip install --upgrade "eltdx==3.4.0"
```

从 `v3.3.1` 升级的兼容性说明：

- 仍然使用 `TdxClient(...)` + `client.f10.*`，无需改动既有调用；`client.f10` 的所有旧方法签名保持不变。
- 唯一需要关注的是 `client.money_flow.history()`：若此前依赖 `count=` 取固定条数，请改为 `days=3|5|10|20|60`（需要固定条数时继续用 `count=`，它现在是客户端切片）。
- 未安装 Rust 工具链时也可直接安装本版本：发布流程同时提供各平台预编译 wheel（abi3，覆盖 Python 3.10–3.14）。
