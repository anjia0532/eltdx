# v3.4.3

## 主要变化

- **指数两融日序列可用**：`market_report()` 新增 `market_margin_summary` 与
  `market_margin_investors` 两个分区，走大盘 F10 的同一个 Entry `CWServ.skef10_dpzx_rzrq`，
  靠 `Params[0]` 区分：`"001"` 活跃个股列表、`"002"` 日序列汇总、`"003"` 投资者情况统计。
  `market_report` 分区数 20 → **22**。

## 修复内容

- **更正「指数两融不可用」**：此前把 `market_margin`（`["001", code]`）只返回活跃个股列表当成
  指数没有两融序列。实际客户端「市场融资融券汇总」页用的是同一 Entry 的 `["002", code]`，
  返回完整日序列。
- **指数两融歧义写进 docstring 与文档**：`trading_report(section="margin_history")` 是**个股**
  两融区间通道（`CWServ.tdxf10_gg_sj` 的 `rzrq_sj`）。拿它查指数（`sh000905` / `sh000001`）时
  服务端按数字代码返回**深市同名个股**——实测 `000905` → 厦门港务、`000001` → 平安银行
  （各约 122 行），不是指数数据。已在 `trading_report` 的 docstring 和
  `docs/methods/F10-交易数据.md` 中标注，并指向正确的两个新分区。
- **`bars.get(all_pages=True)` 翻页合并顺序颠倒**：7709 的 `start` 是「距最新的偏移」
  （start=0 最新），此前按 start=0,800,1600… 顺序拼接，导致最新页在前、最旧页在后，
  页边界时间倒跳（页内升序、整体乱序）。现在按页反转合并，整体**时间升序**
  （最旧在前、最新在后），与 `delisted_bars.get` 对齐；条数与页内数据不受影响。

## 实测数据

| section | Entry | Params | 结果 |
| --- | --- | --- | --- |
| `market_margin` | `CWServ.skef10_dpzx_rzrq` | `["001", "000001"]` | 1676 行活跃个股列表 |
| `market_margin_summary` | `CWServ.skef10_dpzx_rzrq` | `["002", "000001"]` | **8676 行**日序列，2010-03-31 → 2026-10-13 |
| `market_margin_investors` | `CWServ.skef10_dpzx_rzrq` | `["003", "1m"/"3m"/"6m"/"1y"]` | 15 / 60 / 120 / 242 行 |

`market_margin_summary` 的列：`N001` 交易日、`N002` 融资买入、`N003` 融资余额、`N004` 融券余额、
`N005` 两融余额、`N006` 两融差额、`N007`～`N009` 上证 / 深证 / 北证50 收盘价、`N010` 三市标记
（`012001` 沪 / `012002` 深 / `012046` 北 / `total` 汇总）、`N011` / `N012` 科创50 / 创业板指。

> 取全市场汇总时按 `N010 == "total"` 过滤，否则沪 / 深 / 北三套行会混在一起。

## 升级

```bash
python -m pip install --upgrade "eltdx==3.4.3"
```

- 从 `v3.4.2` 升级**无破坏性变更**：只给 `market_report` 增加 2 个 section，并修正两处文档结论。
- 之前用 `trading_report(code, "margin_history")` 查指数的调用请改用
  `market_report(code, "market_margin_summary")`。
- 仍然提供各平台预编译 wheel（abi3，覆盖 Python 3.10–3.14），安装无需本地 Rust 工具链。
